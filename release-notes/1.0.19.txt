The installer builds again
  NSIS reported "no files found" for the payload on this machine, twice: once for the
  folder itself and once for a copy in the temp folder. It was not the payload - the same
  script read build\payload\LICENSE.txt a few lines earlier - and it was not the # in the
  path, because the copy in %TEMP% has no #.

  So the installer no longer asks NSIS to look through a folder at all. Every file is
  listed by name, one SetOutPath + File pair per file, generated from what is on disk by
  tools/gen-filelist.mjs. About 10,000 lines, counted and reported in the build output
  ("Listed 10234 payload files, 214 MB").

  If the list cannot be written, the build says so and stops: a Setup .exe that packs
  nothing is worse than no Setup .exe.

Why the last three attempts failed, in one line each
  1.0.15  the empty-file check measured the wrong path, so everything looked empty
  1.0.16  a real check was added, and it proved the files were there
  1.0.17  assumed the # in the path broke NSIS; it did not
  1.0.18  same, with a fallback copy; both failed the same way, which proved it was the
          wildcard, not the path
