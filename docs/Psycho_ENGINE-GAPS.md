## Sources and scope

- Read-only reference repository `Psycho-Core/PsychoVault---REFERANCE-ONLY`, `Master` at `51a0d717d2feb23ba91126db5e756a08a54e4486`; inspected `app/ui/index.html`, `newtab.html`, `settings.html`, `renderer.js`, and `style.css`.
- The captured contract is pinned separately at `Psycho-Core/PsychoVault` commit `503a596bd89b5aaac979d4f6f86f8465e24c192d`; inventory/hash evidence is in `docs/reference/legacy-inventory.json` and `docs/Psycho_FEATURE-INVENTORY.md`.
- Current rebuild sources are under `engine/`, `runtime/`, `shell/`, and the minimal `ui/` slice. The current P1 Windows flow proves the small address-entry app page, not the reference browser interface.
- `tests/fixtures/p2/` now contains five hand-authored, license-safe HTML/CSS/JS/image cases. Their reference-behavior links and the harness run are below. They are deliberately representative probes, not copies of reference pages or a browser conformance suite.
- The reference renderer calls `window.pv.*`, a runtime-specific legacy bridge. This audit records browser/DOM/CSS/JavaScript requirements exercised by those call sites; it does **not** require copying that namespace. Rebuild UI calls must use the curated `window.psycho` runtime contract and its own schemas.

The reference stylesheet is 684 lines and uses custom properties extensively (about 150 `var()` references), flexbox, grid, focus/hover states, shadows, rounded corners, transitions, animation/keyframes, filters, media queries and custom scrollbars. `renderer.js` (1,201 lines) and `settings.html` (1,521 lines including inline scripts) create and mutate controls dynamically. Representative API use includes `createElement`, `appendChild`, `classList`, `dataset`, `closest`, `matches`, `getBoundingClientRect`, `innerHTML`/`textContent`, focus/select, storage, timers and delegated pointer/keyboard handlers. These are observed consumers, not an instruction to copy implementation details.

Priority: **P0** = blocks the initial reference UI (S080-S083) or correct text/layout; **P1** = major reference interaction/visual gap; **P2** = later polish/long-tail. The named `P2*FixtureRender` checks below are existing runnable S050 smoke regressions. At S050 close, the `Ui*` names were semantic regressions to add at the listed owner step and were explicitly deferred. The dated S051-S060 follow-ups below supersede that snapshot for their named areas. A fixture smoke passing proves only that the page reached paint output and its markers were present; it does not prove the CSS/DOM/API behavior works correctly.

The page caches its last `LayoutResult` against document, computed-style, local-scroll, resource, viewport/layout-width and document-scroll inputs; unchanged frames reuse it. Paint command snapshots produce clipped/coalesced old/new damage bounds, with full-viewport fallback for initial/viewport/resource/canvas changes and unsafe/high-complexity comparisons. The shell maps damage through scroll and zoom, invalidates page-local rectangles, keeps a persistent canvas, rasterizes within the OS invalid rectangle, and transfers only that rectangle. Empty damage does not invalidate.

`tests/Psycho_test_main.cpp` adds S066 regressions for unchanged-frame and nonvisual pointer-move cache reuse, zero damage, and a hover-color transition producing local damage. Linux validation: `python3 tools/Psycho_build.py --compiler gcc --target tests --outdir /tmp/pv-s066-verified && /tmp/pv-s066-verified/pv-tests` passed **996 engine checks / 2,843 total checks**.

This is not dirty-subtree incremental layout: any cache-signature change runs the full layout pass. Paint comparison remains linear and order-sensitive, the shell still traverses the full paint stream under a clip, numerous non-renderer shell interactions still request full-window invalidation, and Windows compilation/interactive GDI/DPI/resize validation has not been performed. See `S066_IMPLEMENTATION.md` for scope and remaining gaps.

## S067 follow-up — tile damage and presentation instrumentation, 2026-11-01

The frame protocol now reports 128px CSS-pixel damage tiles, full-damage state and compositor counters (changed commands, fixed/scrolled paint command counts, and effect groups). The Win32 shell consumes tile damage and uses `DwmFlush()` after GDI flush; it periodically emits paint counts and an approximate missed-refresh estimate to the debugger output. Existing `fixed` paint flags and effect `PushLayer`/`PopLayer` groups feed the layer classification.

`S067CompositorTilesLayersAndFrameMetrics` verifies initial damage tiles, fixed/effect metadata and no tile damage on unchanged frames. Linux validation: `python3 tools/Psycho_build.py --compiler gcc --target tests --outdir /tmp/pv-s067-tests && /tmp/pv-s067-tests/pv-tests` passed **1,040 engine checks / 2,887 total checks**.

This remains a partial compositor implementation. There are no persistent independent raster surfaces for scrolled/transformed/fixed layers, tiles are invalidation units over one software backing canvas rather than separately cached bitmaps, and the estimate is not hardware-present telemetry. Win32 DWM pacing, actual dropped frames, multi-monitor/variable-refresh behavior, and scroll/transform performance need Windows profiling. See `S067_IMPLEMENTATION.md`.
