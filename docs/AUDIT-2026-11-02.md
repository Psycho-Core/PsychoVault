# PsychoVault audit - 2 November 2026

I ran this audit before asking GitHub Actions to build again. It is a source/unit audit, not a device certification, not a legal opinion, and not proof that Proton VPN or leak protection works on a real device.

## What I fixed

- The owned extension engine now passes an `AbortSignal` to handlers, keeps an in-flight slot occupied until a timed-out handler actually settles, limits result size, and re-checks disable/remove after an async host-permission resolve.
- Manifest resource paths reject percent escapes, empty CSP code-source directives are rejected, match-pattern hosts are validated, and path glob matching is linear-time instead of a backtrack-prone regex.
- The Windows extension shim now checks the installed manifest for `proxy` and `privacy` permissions, redacts tab URL/title without `tabs`, refuses proxy takeover/clear by another extension, and rolls back a partially applied proxy change.
- Download open/reveal only accepts paths recorded by PsychoVault's download manager.
- The extension ZIP/CRX reader checks header bounds, entry count, unpacked size and inflated size.
- `docs/THIRD-PARTY-NOTICES.md` no longer claims the legacy `wireproxy.exe` is bundled or run.

## Ownership/provenance conclusion

The Windows application source and `extension-engine/` are Psycho-Core-attributed MIT code. The repository evidence says this is my project code, not a renamed third-party browser.

That is not exclusive ownership. MIT permits reuse. Electron/Chromium/Node remain third-party. Proton VPN remains Proton AG's GPL-3.0 extension. Dark Reader remains MIT third-party code. The current Android APK build is still Titanium/Vanadium-based, not the fully owned Android browser.

## Build decision

The authorized Android APK run 41408123530 was still in progress during this audit. I did not cancel or duplicate it. The audit changes touch the Windows host, owned engine, tests and notices; they do not change the Android APK compile inputs. Windows/Android heavy builds now share one concurrency group so a Windows build queues behind an active APK build instead of racing it.
